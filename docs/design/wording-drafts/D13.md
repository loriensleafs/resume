# D13: the `daycap` push text

Status: wording draft

- Source: SPEC-deploy, "Limit alerts" (the `spend75` row shows the form: a title and one line that names the next step), "Spend limits" (the daily cap pauses the chat until 00:00 UTC) and "Runbooks" (`day-cap.md`: check whether the spend is real or scripted, and raise the cap only if it is real)

## Draft

The `daycap` push goes out once a UTC day, when the daily cap first refuses a turn. Its priority is `urgent`, as for every limit alert.

| Part | Text |
|---|---|
| Title | Chat paused at its $8 daily cap until 00:00 UTC |
| Line | If bun run questions shows real spend, raise the cap in src/ops/limits.ts. |

- The title says what happened and when the chat answers again. 00:00 UTC is 4 pm Pacific in winter and 5 pm in summer.
- The line names the next step. It follows the runbook `day-cap.md`: `bun run questions` shows whether the spend looks real or scripted, and the cap goes up only for real spend. A change to the cap is a release.
- "$8" comes from `dailyCap` in `src/ops/limits.ts`, so the title follows a new cap.
- The code that holds the text: `daycap()` in `src/ops/alerts.ts`.

### For comparison: the `spend75` push

The spec gives this text as one example sentence pair. The code splits it into the two parts of a push, and the title has no full stop:

| Part | Text |
|---|---|
| Title | Chat at 75% of its $20 limit for October |
| Line | Raise it in the Anthropic Console, then in src/ops/limits.ts. |

"75%", "$20" and the month's name come from `src/ops/limits.ts` and the UTC month of the turn. The code is `spend75()` in `src/ops/alerts.ts`. This text is the spec's, so it needs no approval; it is here so that Peter sees both pushes side by side.
